# ADR 0019: IDs and time (D19)

- **Status:** Accepted
- **Date:** 2026-11-08
- **Decision register:** D19 in [Section 0 of the architecture spec](../titan-architecture-spec.md#0-decision-register)

## Context

IDs and time for Titan v1, a local-first Windows desktop application that must share one gaming PC with the
game, OBS and a local LLM.

## Decision

UUIDv7 primary keys generated by the app. All timestamps `timestamptz` UTC. One **session monotonic clock** (`time.perf_counter_ns`, backed by Windows QPC) stamps every event, frame, message, and track start

## Alternatives rejected

Database-generated IDs

## Rationale

IDs sort by time, and every artifact lines up on one timeline for editing.

## Consequences

- `titan_core.ids.uuid7()` generates every primary key; the database never generates IDs.
- `titan_core.clock.SessionClock` stamps events, frames, messages and track starts on one monotonic timeline.
